# Upstream reuse audit

Checked 2026-09-02 against primary source and current public repositories.

## Decision

PEST should own a small Rust runner and Lua bridge. Reuse the **ideas and narrow protocol mechanics** from `reaper-mcp`, the **process/configuration lessons** from `reaper-rs`, and the **API contract** exposed by REAPER. Do not make either project a runtime dependency.

York's scripts and GuiBuh are behavior references, not foundations. Keep `js_ReaScriptAPI` out of V1; consider it only as a pinned, optional desktop-profile dependency if native window discovery is still needed after using REAPER and OS APIs.

## Concrete V1 boundary

Implement only these upstream-informed pieces:

1. A per-scenario directory containing atomic `requests/<id>.json` and `responses/<id>.json` files.
2. A tiny Lua `reaper.defer` loop with `health`, project/track/FX operations, parameter inspection/set, envelope creation, save/load, render coordination, and quit.
3. Stable REAPER GUIDs in responses, explicit request IDs, a heartbeat, deadlines, and “outcome unknown” for timed-out mutations.
4. Official ReaScript calls guarded by capability/version checks.

Skip native extensions, `reaper-rs`, `js_ReaScriptAPI`, GUI automation, MCP/REST, and copied York code until a demonstrated V1 requirement forces one of them in.
